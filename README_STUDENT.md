# 04 基于视觉的道路循迹——学生实验版

本目录由完整例程改编。相机采集、底盘通信、调试显示与异常停车由教师提供；
学生在 `core/line_follower.py` 中补全 `TODO-B1` 至 `TODO-B7`。

## 运行前安全要求

1. 第一次测试先架空驱动轮，确认 `x/z` 符号和限幅正确。
2. 未完成全部基础 TODO 前，占位代码会保持停车，这是预期行为。
3. 实车测试必须保留相机掉线、串口连续发送失败、Ctrl+C 和 `finally` 停车逻辑。

## 基础实验

| 编号 | 学生任务 | 验收要点 |
|---|---|---|
| B1 | 生成梯形 ROI 掩膜 | 掩膜尺寸和类型正确；窗外无前景；上下宽度符合配置 |
| B2 | 固定阈值、手写 Otsu 二值化；自适应阈值为基础拓展 | 黑/白线极性正确；Otsu 不调用 OpenCV Otsu；不同光照下能分离线路 |
| B3 | 扫描行内查找最宽连续线段及滑动搜索窗 | 多干扰段时选择正确；预测窗有效；失线后可全窗重捕获 |
| B4 | 最小二乘拟合、横向误差和方向角 | 左右误差及角度符号正确；数值连续，不明显跳变 |
| B5 | PD 与方向角前馈、限幅 | 六方向偏差能正确纠偏；输出不超过 `max_z`；变化平稳 |
| B6 | 起步速度斜坡和弯道降速 | 起步逐帧加速；直道速度较高；急弯明显降速 |
| B7 | 连续有效帧起步确认和有界失线保护 | 未确认不前进；遮线后按时停车；异常恢复后可重新循迹 |

建议先用视频或静态图逐项验证 B1～B4，再架空车轮验证 B5～B7，最后落地测试。

## 启动示例

```bash
python3 run.py --debug --binary-mode fixed --threshold 100 --max-frames 300
python3 run.py --debug --binary-mode otsu
python3 run.py --port /dev/ttyACM0 --binary-mode otsu
python3 run.py --web --speed 0                 # 先静止调试，打开 http://localhost:9090
python3 run.py --web --web-port 9000 --web-fps 5
```

按 `q`、`Ctrl+C` 或达到 `--max-frames` 后程序停车退出。

## Localhost 实时调试页

加上 `--web` 后，在运行程序的机器上访问 `http://localhost:9090`。
页面会显示原图与拟合线、二值检测图、循迹状态、横向误差、方向角、
速度、转向、FPS、起步确认和失线计数。状态 JSON 也可通过
`http://localhost:9090/api/status` 直接读取。默认仅监听本机回环地址，
不会暴露到局域网。

页面下方可直接修改速度、ROI、扫描区、PD/前馈、限幅和二值化参数。
按“保存并重启”后，服务端会校验参数范围，写入 `web_config.json`，
再依次执行停车、释放设备和自动重启。下次使用 `--web` 启动时也会加载已保存的参数；
显式命令行参数仍可覆盖保存值。

`turn_delay_frames` 用于转向触发延迟，默认为 4 帧（在 20 FPS 下约
0.2 秒）。它只延迟明显弯道的新转向方向；小幅修正和出弯回正不延迟。
`0` 表示关闭，建议实车在 3~6 帧内低速试验。

## 提高实验（只规定任务，不限定实现）

### A1 十字路口

在黑胶带十字路口前可靠识别，并按学生自定策略完成直行、左转或右转。
进入路口前必须明显降速；决策失败、线路重捕获超时、相机或串口异常时必须停车。
教师通过实车连续运行观察识别、动作和驶出路口后的恢复效果。

### A2 左右直角转弯

分别完成黑胶带 90° 左转和 90° 右转。转弯前必须明显降速，转弯过程中不得冲出赛道，
完成后应重新稳定捕获线路并恢复正常巡航；识别失败或动作超时必须停车。

提高部分不提供检测方法、状态机或程序骨架，学生可自行选择视觉特征与控制策略。
